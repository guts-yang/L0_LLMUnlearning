## 2.1 空白 #1（首推）·「可忘性（unlearnability）」：训练期编码塑造 + 事后遗忘的元优化

**交叉坐标**：遗忘时机 = **训练前 / 训练中** × 遗忘算子 = **表征几何 / 目标正则** × 场景 = 单次

**为什么是空白（库内证据，0–3 篇）**
- 【490】*学习时编码塑造遗忘* —— 只做了**观察**（"训练期知识编码选择影响遗忘后效"），**没有提出可优化的编码目标**。
- 【231】NULLs 原生不可遗忘 LLM：共享骨干 + 源特定模块，属**架构隔离**路线，不是"编码几何"路线。
- 【396】梯度路由训练期知识定位、【469】深度无知、【108】安全向量：都是"阻止有害知识形成"，**不是"让已形成的知识变得易删"**。
- 【480】PMC（部分模型塌缩是遗忘的特性）：触及"遗忘与训练动力学的关系"，但属理论侧。
- **净结论：提出一个可优化的「可忘性」训练目标，并量化其与事后遗忘成本的单调关系，库内 0 篇。**

**可发表的问题陈述**
> 现有遗忘研究全部默认知识一旦编码进权重，其可删除性是既定的。我们问一个前序问题：**能否在 SFT 阶段以可微的方式塑造知识的编码几何，使目标知识在事后遗忘时具有显著更低的"遗忘成本"（达成同等遗忘质量所需的效用损失与计算量）？**
> 具体：(i) 定义可忘性度量 $U(f_\theta, \mathcal{D}_f)$ —— 建议基于 forget/retain 梯度夹角的局部条件数（与 HAMU 的 $\kappa$ 同族但用于**训练期**而非遗忘期）；(ii) 在 SFT 损失中加入 $\lambda \cdot U$ 正则；(iii) 证明 $U$ 与事后遗忘成本单调相关；(iv) 给出效用不变的构造性保证。

**为什么适合该研究者**
- 这是一个**双层 / 元学习**问题：外层优化编码正则，内层执行遗忘 —— 天然接得住「进化搜索 / 多目标 / 固定预算」这套工具箱，**且搜索对象从"损失函数"换成了"编码目标"，绕开 EvoMU**。
- 可与 HAMU 的 $\kappa$ 对接：HAMU 用 $\kappa$ 决定"怎么忘"，这里用 $\kappa$ 决定"怎么记" —— 这是一个**干净的对偶叙事**，不是抄袭。

**实验规模估计**：中。
- 需要从 LLaMA-2-7B-base 做一次受控 SFT（可复用 TOFT 的 TOFU 构造法自己造一份，或直接用 `locuslab/tofu_ft_llama2-7b` 做对照组的"未经塑造"版本）。
- 主实验：{有/无} 可忘性正则 × {3 个遗忘算法：GA / NPO / SimNPO} × {TOFU Forget01/05/10} ≈ 18 次 7B LoRA 遗忘 + 6 次 SFT。
- 单机（8×A100/H100 级别）**约 200–350 GPU 时**，6–9 个月可完成含消融与写作。

**风险**
- 🔴 **最大风险**：审稿人问"这是否只是让模型记得更浅？"——必须证明 retain utility / 通用能力（MMLU、TruthfulQA、AlpacaEval）**不降**，且遗忘前的下游表现持平。
- 🟡 中：可忘性度量 $U$ 若与 HAMU 的 $\kappa$ 过于相似，会被判增量。**对策：把 $U$ 定义在训练期（优化前的梯度几何）而非遗忘期，并给出理论上界。**
- 🟢 低：算力完全可控。

## 2.2 空白 #2（性价比最高）· 部署格点不变遗忘（Deployment-Lattice Invariant Unlearning）

**交叉坐标**：评估口径 = **部署后** × 算子 = 任意 × 场景 = 单次 → 升级为 **组合不变性**

**为什么是空白（库内证据，单轴各 2–6 篇，交叉 0 篇）**
- 量化轴：【54】SURE（量化致遗忘失效）、【152】GROM（闭式解天然抗量化）、【259】量化永久遗忘（电路归因）、【276】DurableUn（INT4 QRA 攻击）、【327】LoRA 低秩抗量化、【348】QUAIL（量化感知遗忘）。**6 篇。**
- 剪枝轴：【333】稀疏化感知遗忘。**1 篇。**
- 下游微调轴：【71】ILU（不变性表示使遗忘抗下游微调）、【514】权重空间正则抗再学习。**2 篇。**
- 蒸馏轴：【UNDO】蒸馏鲁棒化遗忘、【537】均值教师。**2 篇。**
- **但：没有任何一篇做「量化 bitwidth × 稀疏率 × 下游 LoRA 步数 × 蒸馏」的组合压力测试，也没有给出跨格点的联合保证。**
- 更关键：**已有结论互相打架** —— 【434】发现"用更简单的优化器反而更抗逆转"，【327】说"全参数更新太分散撑不过 4bit，LoRA 更抗"，【54】说"要大学习率局部更新"。这些是**互斥的机制解释**，说明这个空间还没被理清。

**可发表的问题陈述**
> 定义**部署格点** $\mathcal{G} = \mathcal{B}\times\mathcal{S}\times\mathcal{T}\times\mathcal{K}$（bitwidth × 稀疏率 × 下游微调步数 × 蒸馏温度/轮数）。现有遗忘只保证 $\mathcal{G}$ 中单点（通常是 BF16、无剪枝、无微调）成立。我们研究：
> (i) **组合失效的刻画**：遗忘在 $\mathcal{G}$ 上是否单调/可分解？是否存在"量化安全 ⟹ 剪枝安全"的蕴含关系？（预期答案：**否**，给出反例）
> (ii) **部署不变性正则**：在遗忘目标中加入跨格点一致性项，使遗忘在整个 $\mathcal{G}$ 上一致成立，而不是只在 BF16 审计点成立。

**为什么适合该研究者**
- **搜索空间天然多目标**：每个格点是一个目标（或约束），这正是 NSGA-II / 帕累托的用武之地，而且**把"多目标"从 HAMU 已经占了的 (forget, retain) 二维，升维到 (forget, retain, |G| 个部署点)** —— 这是 HAMU / OFMU / MUNBa 都没做的，构成真实 delta。
- 算力极低：7B LoRA + INT4/INT8 量化 + 20/40% 剪枝 + 下游 LoRA，3×3×3 = 27 个格点 × 4 种遗忘算法 ≈ 108 次短程微调，每次 0.5–1.5 GPU 时 → **约 100–160 GPU 时**。3–5 个月可完成。

**风险**
- 🟡 **被判"只是工程评测"**：必须给出 (ii) 的可优化目标，而不只是报告一张 27 格点的表。对标【71】ILU 的做法（学不变表示）。
- 🟡 与【54】【276】【327】【259】高度相邻 —— **必须把它们作为 related work 正面处理，并指出"单轴结论互斥"这一矛盾作为立论起点**。
- 🟢 算力风险极低；结果确定性高（几乎必然能画出有趣的失效图）。

## 2.3 空白 #3 · 参数 × 外置记忆的联合遗忘不动点

**交叉坐标**：遗忘对象 = **外置记忆 / RAG** × 算子 = **系统级 + 权重** × 时机 = 训练后

**为什么是空白（库内证据，3–4 篇，且无方法）**
- 【215】有限记忆 LM 的遗忘审计：FULL / DEL-ON / DEL-OFF 三态因果干预，**只做审计、不给方法**。
- 【57】ERASE：把微调数据外置为 ICL 示例，删数据即删 ICL 示例 —— 是"规避遗忘"而非"联合遗忘"。
- 【437】CURE 检索排除纠正、【453】定制 RAG 推荐去偏、【293】MAGE 记忆图：单侧处理。
- 【201】持久记忆（Kimi Delta Attention）中的精确删除：**给出否定性结果**，说明这条轴有硬骨头。
- 【325】Agentic Unlearning 提出"**参数-记忆回流**"（检索复活参数残余、记忆工件重引入敏感内容）—— **唯一一篇点破双通道，但限定在 Agent 场景，且是方法+评估混合，没有形式化。**
- **净结论：非 Agent 场景下，「参数遗忘 × 语料删除」的联合形式化与不动点求解，库内 0 篇。**

**可发表的问题陈述**
> 当目标知识同时存在于模型参数与外置检索语料中时，遗忘是一个**互为条件**的问题：删参数而语料在 → 检索复活；删语料而参数在 → 参数再生。我们把联合遗忘定义为算子对 $(U_\theta, U_\mathcal{C})$ 的不动点：
> $\theta^\star = U_\theta(\theta^\star, \mathcal{C}^\star),\ \mathcal{C}^\star = U_\mathcal{C}(\mathcal{C}^\star, \theta^\star)$
> 研究：(i) 该不动点是否存在/唯一？(ii) 交替执行朴素遗忘是否收敛到它，还是陷入"回流震荡"（给出反例）？(iii) 给出收敛的联合算法与停止准则。

**为什么适合该研究者**
- 可以用 TOFU 直接构造受控设定：先在 TOFU 上 SFT（参数含知识），再把 forget set 作为 RAG 语料（语料含知识）—— **零额外数据成本**。
- 不动点/收敛性与"多目标 + 固定预算"的表述天然契合。

**实验规模估计**：中低。7B + 一个 40k 段落级语料 + FAISS，单机可跑。约 150–250 GPU 时（含 attack 侧的检索复活评估）。

**风险**
- 🟡 中：需要把"不动点"讲得让 ML 审稿人买账，不能写成纯 IR 论文。
- 🟡 中：【325】已于 2026 年出现，必须做严格差异化（Agent vs 通用 RAG；方法 vs 形式化）。
- 🟢 算力可控。

## 2.4 空白 #4 · 长 CoT 中"遗忘干预的持久性"（推理时 × 推理链级）

**交叉坐标**：对象 = **推理链级** × 时机 = **推理时** × 算子 = **激活/上下文干预**

**为什么是空白（库内证据，1 篇）**

- 唯一交叉点：【184】ST2U 提到"激活编辑被后续生成洗白回受限知识区" —— **提出了问题但只在短生成上做**。
- **净结论：长 CoT（数百至数千 token）下的推理时遗忘干预，库内 0–1 篇。**

**可发表的问题陈述**
> 在长链式推理中，第 $k$ 步施加的遗忘干预会被后续 $L-k$ 步的自回归生成逐步稀释。定义**干预衰减率** $\rho(k, \ell, L)$（干预层 $\ell$、干预位置 $k$、总链长 $L$）。研究：(i) 刻画 $\rho$ 关于 $L$ 与 $\ell$ 的渐近行为（是否与残差流累积成正比衰减）；(ii) 是否存在"干预调度"（在哪些步、哪些层重复施打）使遗忘在整个轨迹上持久；(iii) 给出持久性的下界与最小干预次数。

**实验规模估计**：中。**需要 LRM**（DeepSeek-R1-Distill-Qwen-7B / QwQ 级别），7B 单机可跑推理，但要跑长 CoT 的批量采样，成本高于普通 SFT。约 200–400 GPU 时。

**风险**
- 🔴 **高**：CoT 级遗忘的评估指标极不成熟（R-TOFU【525】2026 才出，步骤级指标尚无共识）。

- 🟡 中：需要额外模型栈，与现有 TOFU/LLaMA-2 基线不复用。

**可发表的问题陈述**
> 把终身遗忘形式化为受约束的序列决策：第 $t$ 个删除请求产生三维代价 $(q_t, u_t, c_t)$ =（遗忘彻底度, 效用损失, 计算）。总约束 $\sum u_t \leq U,\ \sum c_t \leq C$。
> 研究：(i) 证明**单步帕累托最优 ≠ 序列帕累托最优**（给出构造性反例，例如先来一个"硬"请求会耗尽后续所有请求的可行域）；(ii) 给出序列帕累托策略的近似算法与 regret 界；(iii) 在 TOFU 顺序删除 + MUSE 上验证。

**风险**

- 🟡 中：需要 regret 界一类的理论，否则沦为调度启发式。

## 2.6 空白 #6 · 服务侧遗忘：KV Cache / 前缀缓存 / 会话态（系统级算子）

**交叉坐标**：算子 = **系统级** × 时机 = **推理时 / 部署后** × 对象 = **系统态**

**为什么是空白（库内 0–1 篇）**
- 【64】System-Aware 遗忘（2024）：提出"缓存、数据处理等系统组件应纳入遗忘范围"，但**是 CV/分类语境，且只提了观点没做 LLM**。
- 库内没有任何一篇处理 **KV cache / 前缀缓存（prefix cache）/ 会话历史 / 推理日志** 中的遗忘。
- 相关但不同：【221】CBD API-only 黑盒遗忘、【57】ERASE（ICL 外置）、【ALU】Agent 工作流遗忘。

**可发表的问题陈述**
> 推理服务普遍启用前缀缓存（vLLM / SGLang 的 automatic prefix caching）。模型权重已完成遗忘，但缓存中仍留存包含目标内容的 KV —— **任何命中该前缀的请求都会复现已"遗忘"的内容**。
> 研究：(i) 形式化「服务侧遗忘」（serving-time unlearning）的威胁模型与可验证性定义；(ii) 给出缓存侧的遗忘协议（失效/重写/隔离）及其与权重侧遗忘的**组合完整性**证明；(iii) 度量缓存命中率损失这一新的效用维度。

**实验规模估计**：**低**。7B + vLLM 前缀缓存 + 一个缓存命中 trace，几乎不需要训练。约 50–100 GPU 时 + 系统实现工作量。

**风险**
- 🟡 中：**venue 匹配风险** —— 纯系统贡献在 NeurIPS/ICML 可能被嫌"engineering"，但非常适合 USENIX Security / S&P / CCS / OSDI，或 NeurIPS Datasets & Benchmarks。
- 🟡 中：需要系统实现能力（改 vLLM 缓存层），若团队无此储备则推行困难。
- 🟢 新颖性极高，几乎无竞争。

## 2.7 空白 #7 · 遗忘前审计：Out-of-Knowledge 请求的判定与分流

**交叉坐标**：评估口径 = **遗忘前** × 问题定义 = **知识在场性（knowledge presence）**

**为什么是空白（库内 2 篇提出问题，0 篇给方法）**
- 【190】*Confess What You Know*：定义两类 forget-set 错配 —— **Under Unlearning**（漏删）与 **Out-of-Knowledge Unlearning**（**逼模型"忘掉"它从未学过的知识，结果白白扰动参数**）。**只定义，无方法。**
- 【477】*LLM 该忘什么*（ECML）：量化"哪些个人事实真在模型里"，**只到审计，未接到遗忘执行**。
- 【573】*哪个保留集重要*：研究 retain set 构成的影响，侧面说明"输入侧因素被忽视"。

**可发表的问题陈述**
> 真实 GDPR/RTBF 请求流中，相当比例的目标知识**根本不在模型中**（或已被先前遗忘移除）。现行遗忘管线会对这些请求照常执行反向优化，**凭空引入参数扰动与效用损失而不产生任何遗忘收益**。
> 研究：(i) 构造遗忘前的**知识在场审计器**（knowledge-presence auditor），输出"该目标是否需要遗忘"的三路决策 {真遗忘 / 拒绝执行 / 转为拒答}；(ii) 给出审计器的 ROC 与误判成本模型；(iii) 证明在真实请求分布下，接入审计器可显著降低累积效用损失。

**实验规模估计**：**低-中**。7B + TOFU（天然可构造"模型没学过的虚构作家"作为 Out-of-Knowledge 请求）+ 一个真实请求分布模拟。约 100–200 GPU 时。

**风险**
- 🟡 中：需要"真实请求分布"的可信假设，否则被质疑设定人为。
- 🟡 中：【190】【477】已占问题定义，**方法必须是新的**（不能只是"训练一个分类器"）。
- 🟢 实用性强、评审友好、算力低。

## 2.8 空白 #8 · 遗忘式归因的统计可识别性（遗忘 × 数据归因的反向利用）

**交叉坐标**：算子 = **遗忘** → 用作**归因估计量** × 理论口径

**为什么是空白（库内 4 篇用它，0 篇分析它）**
- 【82】遗忘合成图像做 T2I 数据归因；【105】GRACE 用遗忘解密预训练语料影响；【623】UNI 用（un）学习基线替代静态归因基线；【246】把遗忘目标重述为"置零数据归因"。
- **四篇都默认"遗忘 X 后 Y 的损失变化 = X 对 Y 的影响"，没有一篇给出这个估计量的偏差/方差分析，也没有与 influence function（EK-FAC / DataInf / TRAK / LiSSA）做系统对照。**

**可发表的问题陈述**
> 把"遗忘式归因"$\hat{I}(x \to y) = \mathcal{L}_y(\theta_{\setminus x}) - \mathcal{L}_y(\theta)$ 视为一个**估计量**，分析其在非凸深度模型上的三种偏差来源：(a) 路径依赖（SGD 轨迹不唯一）；(b) 顺序效应（遗忘 $x_1$ 后再忘 $x_2$ ≠ 反序）；(c) 优化噪声（近似遗忘 vs 精确重训的 gap）。给出偏差上界，并与 EK-FAC/TRAK 在受控测试床（Hubble 记忆研究套件【421】）上做对照，给出"何时遗忘式归因优于/劣于影响函数"的可操作判据。

**风险**
- 🔴 **高**：纯分析类，需要很强的理论；且归因社区本身对"非凸下影响函数不可靠"已有大量批评，需要真正的增量。
- 🟡 中：理论 + 实证双线，周期可能超过 12 个月。
- 适合作为**方向 A/G 之外的备用方向**，不推荐作为 6–12 个月的主攻。

## 4.4 差异轴分析：MOGP-U 还剩什么？

把 MOGP-U 拆成四个可分离的卖点，逐个判定是否被占：

| 卖点 | 是否被占 | 占据者 | 判定 |
|---|---|---|---|
| **S1：用进化/自动搜索找遗忘损失** | 🔴 **已被占** | EvoMU（2602.02139，代码开源，TOFU/MUSE/WMDP 已超过 NPO） | **不成立为独立贡献** |
| **S2：显式多目标（帕累托）而非标量化加权和** | 🔴 **已被占** | HAMU（ICML 2026，约束式，同基座）、OFMU（双层）、MUNBa（Nash）、RAUL（UPGrad）、FUPareto（MGDA）、2410.22086（动态标量化） | **不成立为独立贡献** |
| **S3：语义 DSL / 语法约束的程序表示** | 🟡 **部分被占** | 通用损失搜索里有 GP 树（GLO/TaylorGLO/EvoMAL），但**遗忘领域内只有 EvoMU 的 LLM 自由代码版，没有语法约束版** | **真实但狭窄的差异** |
| **S4：可审计性 / 形式可验证** | 🟢 **未被占** | 库内【21】【25】【407】只是**呼吁**可审计，无人实现 | **最干净的差异点** |
| **S5：固定预算搜索** | 🟡 弱差异 | EvoMU 已让 LLM 提议训练预算 | 不足以独立成立 |

**核心判断（诚实版）：**

> **「用进化算法 / 多目标优化搜索遗忘损失」这个想法，其两个主卖点（S1 搜损失、S2 多目标）都已被占据。**
> - S1 被 **EvoMU（arXiv:2602.02139，2026-02）** 占据，且**用了几乎相同的技术配方**（进化搜索 + LoRA + TOFU/MUSE/WMDP + 超 NPO），代码已开源。
> - S2 被 **HAMU（arXiv:2606.02119，ICML 2026）** 占据，且 **HAMU 的实验设置与研究者几乎完全重合**（Llama-2-7b-chat + TOFU）。
>
> **如果 MOGP-U 的 abstract 写的是"现有方法用标量化加权和，我们用多目标进化搜索遗忘损失"，那么它在 2026 年的审稿环境下会被同时引 EvoMU 与 HAMU，判为 concurrent / incremental。**

**仍然可发的三个改法（按推荐度）**

1. **换搜索对象**（推荐）：不搜"遗忘损失"，搜**"可忘性编码目标"**（空白 #1）或**"部署不变性正则"**（空白 #2）。进化/多目标工具箱原样保留，问题域是空的，且与 HAMU 构成"怎么忘 vs 怎么记"的对偶而非竞争。

2. **把多目标升维**（推荐）：从 (forget, retain) 二维升到 **(forget, retain, $|\mathcal{G}|$ 个部署格点)**（空白 #2）。HAMU/OFMU/MUNBa 全部只在 2 维上做，升维是结构性差异，且有【54】【276】【327】【259】【434】这些**互相矛盾的单轴实证**作为立论支点。

3. **打 EvoMU 的软肋（高风险高回报）**：EvoMU 自己承认 *"there might not even exist a universally optimal loss function"* 并因此只做 dataset-specific。若能用 DSL 的符号结构 + 帕累托前沿搜出**跨基准可迁移的损失族**（在 TOFU 上搜，零成本迁移到 MUSE/WMDP 仍超 NPO/SimNPO），这是**对 EvoMU 的正面反论点**，delta 极清晰。
   - **风险**：可能失败 —— 也许真的不存在可迁移损失；若失败则论文只剩"我们搜了但搜不出来"的负面结果（除非包装成 impossibility 分析，那又是另一种论文）。

| **输出物** | 一个算法 + 停止准则 | 一组符号损失 + 帕累托前沿 | 🟢 不同 |
| **代码** | 已开源（github.com/aoi3142/HAMU） | — | — |

**裁决**：
> **【HAMU】与 MOGP-U 在多目标这一动机上直接冲突，且实验设置高度重合。**
> - 若 MOGP-U 以"显式多目标替代标量化"为主卖点 → **不可发**（HAMU 已做，且有理论、有阈值、有停止准则、有 ICML）。
> - 若 MOGP-U 以"搜索可审计的符号损失"为主卖点、多目标仅作为**搜索过程的机制**（而非论文的贡献点）→ **仍可发**，但必须在 related work 中把 (a) EvoMU（同为搜索）、(b) HAMU（同为多目标）**分别显式区分**，并把差异钉死在 **可审计性（S4）** 上。
> - **最稳妥的做法**：把 HAMU 的 $\kappa$ 作为 DSL 的一个**可用原语**并入搜索空间（"我们搜索的损失可以调用难度感知门控"），把 HAMU 从竞争者变成组件 —— 这是审稿人最喜欢的姿态。

## 4.6 【443】OFMU 与 MOGP-U 的比对

| 维度 | OFMU（2509.22483） | MOGP-U（设想） | 冲突？ |
|---|---|---|---|
| **问题表述** | "多目标问题常被**标量化**为加权和 → 梯度冲突 → 训练不稳定" | "标量化不行，要显式多目标" | 🔴 **同一立论，直接冲突** |
| **解法** | 惩罚式**双层优化**（内层最大化遗忘 + 相似度感知梯度去相关；外层最小化保留损失），双循环算法 | 进化搜索 + NSGA-II 帕累托 | 🟢 解法不同 |
| **理论** | 凸/非凸收敛保证 + 收敛率 | — | 🟡 **注意：pith.science 的自动审查指出 OFMU 的收敛证明存在反例风险**（"desk verdict: a plausible empirical recipe, but the convergence proofs are invalid"） |
| **基准** | TOFU、WMDP、CIFAR-10/100；LLaMA-2 / LLaMA-3 | TOFU Forget05 | 🔴 **基准重合** |
| **Baseline** | 已对比 NPO / SimNPO / RMU / GradDiff，并声称全面胜出 | — | 🔴 **研究者的 SOTA baseline（SimNPO）已被 OFMU 作为手下败将列出** |

**裁决**：
> **【443】OFMU 与 MOGP-U 在多目标/帕累托框架这一表述上直接冲突。**
> - OFMU 明确把"标量化不行"作为立论，并用双层优化替代；而且它已经在 TOFU 上把 SimNPO 列为 baseline 并声称超越。**这意味着研究者"先复现 SimNPO 锁 SOTA"的策略，在 OFMU 面前已经不够** —— 需要把 OFMU 也纳入对比（OFMU 有 arXiv 预印本但理论存疑，可与之一战）。
> - **战术机会**：OFMU 的收敛证明被自动审查标为可疑。若研究者能 (i) 复现 OFMU 并指出理论漏洞，(ii) 同时给出自己的解法，这会是一篇很有力的论文。但**打一个 2025-09 的预印本作为主贡献风险高、收益低**，建议只作为 related work 的一个"待商榷"引注，不作为靶子。
> - **净结论**：**不要以"多目标/帕累托框架"作为 MOGP-U 的卖点。**

## 4.7 方向 G（ES-MU：进化策略 × 大规模遗忘）的核查 —— **结论：空白，且是当前最干净的一个**

联网检索结果（2026-09-08）：

| 检索 | 结果 |
|---|---|
| ES + 遗忘（作为**优化方法**） | **未检索到任何一篇用 ES/零阶优化直接执行遗忘的工作** |
| ES + LLM 微调 | 已有大量工作：Cognizant AI Lab「Evolution Strategies at Scale: LLM Fine-Tuning Beyond RL」、Hyper-ES（CMA-ES 合并 DARE-TIES 系数）、EGGROLL、ESSA、Quantized ES、EA4LLM 等 |
| ES 导致**灾难性遗忘** | arXiv:2601.20861（UC Berkeley, 2026-01）系统证明 ES 微调引发严重灾难性遗忘（更新 $\ell_2$ 范数比 GRPO 高 3 个数量级、稀疏性远低）；AWD（arXiv:2605.30148, Cognizant）用锚定权重衰减修复 |
| ES + 遗忘（间接） | REBEL（2602.06248）：进化算法生成**对抗提示**做**评估**，不是优化遗忘本身 |

**判定**：
> **「ES / 零阶优化作为遗忘的执行算子」目前是空白。**
> 而且这个空白有非常漂亮的立论：
> - arXiv:2601.20861 证明 **ES 更新是"全局稠密 + 大范数"的**，而【327】发现 **全参数微调的遗忘撑不过 4bit 量化，LoRA（低秩集中）才抗量化** —— 两条实证结合起来直接暗示：**ES 式的大范数稠密更新做出来的遗忘，在部署格点上会非常脆弱**。这是一个可以做、也可以证伪的具体假设。
> - 反过来：若对 ES 加低秩/稀疏约束（AWD 的锚定 + LoRA 参数化），可能得到**既免反向传播、又抗部署扰动**的遗忘算子 —— 这在**黑盒 API 场景**（【221】CBD）和**内存受限场景**有真实价值。
>
> **但要注意语义陷阱**：【149】AWD 讲的是"ES 微调引发的**灾难性遗忘**（catastrophic forgetting）"，这是持续学习意义的 forgetting，**不是机器遗忘**。写 related work 时必须显式区分这两者，否则会被审稿人认为概念混淆。

**方向 G 的风险**：
- 🟡 中：**为什么要用 ES 做遗忘？** 如果答案只是"免梯度"，动机偏弱（遗忘本来就有梯度）。必须找到 ES 的**不可替代优势**，建议锚定：(a) 黑盒/API-only 遗忘（【221】CBD 已开这条线，但只做行为分歧）；(b) 不可微目标（如"通过 MIA 审计"这类离散指标，【42】用隐式函数定理可微化，ES 可绕过）；(c) 多目标帕累托前沿的免梯度探索。
- 🟡 中：ES 在 7B 上的种群评估成本高（每次评估 = 一次前向），但 LoRA 参数化 + 种子重构（【146】）可压到很低。

**与方向 A（MOGP-U）的组合建议**：
> 方向 A 被挤压，方向 G 是空白 —— **建议把 A 的"多目标搜索"能力迁移到 G 上**：用 ES/多目标进化在 **LoRA 低秩子空间**里搜索遗忘更新方向，目标是 (forget, retain, 部署格点鲁棒性)。这样既保留了研究者的核心工具箱，又落在完全没人做的格子里，且与【327】【2601.20861】两条实证直接对话。

## 附：一页纸执行建议

**不要做**
- ❌ 再提一个 NPO/SimNPO 变体损失函数
- ❌ 再做多模态/扩散/联邦/图/推荐遗忘
- ❌ 再做"现有方法其实没忘"的第 N 个基准/攻击
- ❌ 以"多目标/帕累托框架"作为论文主卖点（HAMU/OFMU/MUNBa/RAUL/FUPareto 已占）
- ❌ 以"进化搜索遗忘损失"作为论文主卖点（EvoMU 已占，还开源了代码）

**可以做（按推荐度）**
1. **空白 #2 · 部署格点不变遗忘** —— 把多目标从 2 维升到 $2+|\mathcal{G}|$ 维，算力最低、确定性最高、与【54】【276】【327】【259】【434】的互斥实证直接对话。
2. **方向 G 升级 · ES/零阶 × 低秩子空间 × 部署鲁棒遗忘** —— 目前是**完全空白**，且与 arXiv:2601.20861（ES 更新大范数稠密）+ 【327】（全参遗忘不抗量化）两条实证构成可证伪假设。
3. **空白 #1 · 可忘性（learn-to-be-unlearnable）** —— 与 HAMU 构成"怎么忘 vs 怎么记"的对偶叙事，进化/元优化工具箱可直接迁移。
4. **空白 #3 · 参数 × 外置记忆联合遗忘不动点** —— 可用 TOFU 零成本构造受控设定，贴合 RAG 时代。

**跨方向的一条铁律**
> 无论选哪个，**都不要把"多目标"写成贡献点** —— 2026 年它已经是 baseline 常识（HAMU 甚至给了理论阈值和停止准则）。把"多目标"写成**方法**（搜索机制 / 决策框架），把贡献点钉在**问题**（部署格点 / 可忘性 / 联合遗忘 / ES 算子）上。
